# Amplicon-model calibration and execution backends

The genotype model already exposes PCR-product efficiency, dropout and artifact
terms.  This layer estimates those terms from declared controls without pretending
that another caller is ground truth or that WGS calibrates a multiplex-PCR assay.

## Control contract

Each calibration row declares:

```text
sample_id
molecules_tsv
haplotype_1
haplotype_2
stratum
truth_status
truth_source
assay_scope
```

Allowed truth states are certified reference material, orthogonally resolved,
assembly resolved, synthetic and comparator only.  `assay_scope` states whether
the reads were produced by the target assay, a synthetic implementation of that
assay, WGS, or a caller comparator.

By default:

- target-assay and synthetic-assay controls are eligible;
- WGS and other non-assay-matched data are excluded;
- DRAGEN/vendor/caller comparators are excluded; and
- controls below the declared effective-evidence floor are excluded.

Every exclusion is retained in the calibration JSON.

## Relative product efficiency

For a control sample `s` with known chromosome-haplotype pair, let `m_sp` be the
compiled multiplicity of product `p`, `e_p` its relative efficiency and `d_s` a
sample-specific exposure.  The fitted mean is

```text
mu_sp = d_s * m_sp * e_p.
```

NanoGlobin alternates between sample exposures and product efficiencies, with an
explicit prior toward the declared starting efficiency.  Efficiencies are
normalised geometrically because only relative product composition is observed.
Absolute library size is not copy number.

### Identifiability graph

Products are linked when at least one eligible control genotype is expected to
produce them together.  Relative efficiency is estimable only inside a connected
component of this graph.

- A single product has no independently identifiable relative efficiency.
- Two disconnected product sets have no identified common scale.
- A product absent from every eligible control retains its declared prior.
- Expected products never observed are reported as a weak fit rather than silently
  assigned zero efficiency.

These states are emitted in `product_parameters.tsv` and `calibration.json`.

## Dropout and unsupported molecules

Required-product dropout is estimated from control/product detection trials with a
Beta prior.  The global posterior mean is used by the current genotype model;
product-specific posterior summaries are retained for diagnostics and a future
product-specific dropout likelihood.

Unsupported complete molecules are those whose assigned product/compiled sequence
is not generated by the known control genotype.  Their effective mass is modelled
with a separate Beta prior and updates `artifact_probability`.

Neither estimate converts PCR descendants into independent molecules.  Calibration
uses the same assignment weights and effective-evidence cap as the model.

## Batch, lot and operator strata

The manifest's `stratum` field can encode a lot, run, operator, laboratory or a
composite value.  When enough controls exist, each stratum receives an
empirical-Bayes fit shrunk toward the global product efficiencies, dropout and
artifact estimates.  Separate YAML configs are optional outputs.

This is the first useful hierarchical layer.  It does not claim that two controls
per lot establish production-level lot validation; the output records the number
of controls and fitting status.

## Commands

```bash
python scripts/calibrate_amplicon_model.py \
  --compiled-json results/assay/compiled_products.json \
  --control-manifest validation/controls.tsv \
  --base-model-config examples/genotype_inference.example.yml \
  --calibration-settings examples/calibration_settings.example.yml \
  --calibration-json results/assay/calibration/calibration.json \
  --calibrated-model-config results/assay/calibration/calibrated_model.yml \
  --product-parameters-tsv results/assay/calibration/product_parameters.tsv \
  --sample-product-fit-tsv results/assay/calibration/sample_product_fit.tsv
```

Then genotype a held-out sample with provenance checking:

```bash
python scripts/genotype_amplicons.py \
  --compiled-json results/assay/compiled_products.json \
  --molecules-tsv results/assay/molecules/HELD_OUT.molecules.tsv \
  --model-config results/assay/calibration/calibrated_model.yml \
  --calibration-json results/assay/calibration/calibration.json \
  --backend auto \
  --posteriors-tsv results/assay/genotypes_calibrated/HELD_OUT.posteriors.tsv \
  --call-json results/assay/genotypes_calibrated/HELD_OUT.call.json \
  --summary-json results/assay/genotypes_calibrated/HELD_OUT.summary.json
```

The calibration JSON embeds the exact calibrated model configuration.  Inference
fails if `--model-config` does not match it.

A standalone Snakemake layer is available:

```bash
snakemake -s Snakefile.calibration --use-conda --cores 4
```

## Cython backend

RapidFuzz already performs full-sequence edit distance in native code.  Rewriting
that path in Cython would add little.  The new Cython kernel instead accelerates
the remaining class-by-evidence stage:

1. apply the same evidence weights and caps as the Python reference;
2. group reads with identical product, sequence-hash and candidate-haplotype state;
3. encode genotype classes as dense product/key matrices;
4. score molecule compatibility, Dirichlet-multinomial composition and dropout
   without the GIL; and
5. reconstruct the same `GenotypeClassScore` objects and normalize in Python.

`--backend python` is the semantic reference.  `--backend cython` fails closed if
the extension is unavailable.  `--backend auto` selects Cython when the extension
is built and the current uint64 candidate mask can represent the catalogue; it
otherwise reports the explicit Python fallback reason.

Build and benchmark:

```bash
python setup.py build_ext --inplace
python scripts/benchmark_genotype_backend.py \
  --compiled-json results/assay/compiled_products.json \
  --molecules-tsv results/assay/molecules/SAMPLE.molecules.tsv \
  --model-config results/assay/calibration/calibrated_model.yml \
  --warmups 2 --repeats 10 \
  --output-json results/benchmarks/SAMPLE.genotype_backend.json
```

The benchmark first requires numerical parity for all likelihood terms and
posteriors.  It then reports every timing, minimum, median, mean, maximum and
population standard deviation.  A single favourable timing is not accepted as a
performance result.

## Calibration is not validation

Fitting on controls does not establish analytical performance.  Freeze the assay
profile, haplotype catalogue and calibrated parameters, then evaluate an
independent blinded set.  Report sensitivity, specificity, ambiguity, no-call
rate, calibration and discordances by event class.  See
[`../validation/README.md`](../validation/README.md) for the acquisition plan.
