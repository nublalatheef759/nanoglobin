# Candidate chromosome-haplotype posterior

## State space

Let `h` denote a sequence-resolved chromosome haplotype. Each `h` may contain any
number and order of HBA-like copies, hybrid genes and linked small variants. The
sample state is an unordered diploid pair:

```text
G = (h1, h2).
```

This is already a variable-copy HBA model because copy number is a property of each
chromosome haplotype, not organismal ploidy.

## Observable genotype classes

The assay compiler emits the exact product sequences generated by every haplotype.
For each pair, the model constructs a count-aware multiset of
`(product_id, sequence_hash, multiplicity)`. Named pairs with the same multiset are
collapsed into one observable class before assigning the default prior.

This prevents three synonymous catalogue labels from receiving three times the
prior mass of one sequence state and makes intrinsic assay ambiguity an output of
the model rather than a downstream caveat.

## Likelihood

The transparent score is:

```text
log L(G) =
    log L_read(G)
  + log L_product_counts(G)
  + log L_required_products(G)
  + log prior(G).
```

### Molecule compatibility

Complete primer-admitted reads contribute according to product assignment, compiled
sequence hash, candidate haplotypes and assignment quality. Exact sequence
compatibility receives high probability; unsupported products receive the explicit
artifact probability. Low-margin or poor-fit observations are down-weighted.

An effective-read cap prevents thousands of PCR descendants from being treated as
thousands of independent genomic molecules.

### Product composition

A Dirichlet-multinomial score compares observed product composition with expected
multiplicity multiplied by explicit product-efficiency parameters. Background mass
prevents an impossible zero likelihood and exposes unexpected products.

With only one product and no external control, absolute copy multiplicity remains
unidentifiable. The posterior should then stay ambiguous rather than extracting
copy number from library size.

### Required-product dropout

Expected required products receive a dropout probability when absent and a
`1 - dropout` term when observed. The parameter may be declared for sensitivity
analysis or estimated from truth-scoped assay-matched controls.

The calibration layer also retains product-specific dropout summaries. The current
posterior intentionally uses one global required-product probability until the
product-specific model has enough replicated controls to be identifiable and
validated.

### Priors

The default prior is uniform over observable product signatures, not over every
catalogue label. Optional haplotype-frequency priors are accepted only when every
candidate haplotype is assigned explicit mass. Likelihood-only and prior-sensitive
results should both be inspected when population priors are uncertain.

## Calibration provenance

`calibrate_amplicon_model.py` estimates relative product efficiencies, global
dropout and unsupported-molecule mass from controls that declare:

- the known chromosome-haplotype pair;
- truth method/source;
- assay scope; and
- run, lot, operator or laboratory stratum.

WGS and comparator-only controls are excluded by default. Relative efficiency is
estimated only within connected product groups whose products co-occur in at least
one eligible control genotype. Isolated and disconnected scales are reported as
unidentifiable.

The emitted calibration JSON embeds the exact fitted `GenotypeConfig`. A downstream
call fails when its model config does not match the calibration provenance. See
[`MODEL_CALIBRATION.md`](MODEL_CALIBRATION.md).

## Call states

- `RESOLVED_RESEARCH_CALL`
- `AMBIGUOUS_ASSAY_EQUIVALENT`
- `AMBIGUOUS_POSTERIOR`
- `NO_CALL_INSUFFICIENT_EVIDENCE`

The reported probability is conditional on the candidate catalogue, assay profile,
calibration controls and current model. Calibration controls must be separated from
the held-out analytical evaluation set.

## Execution backends

The Python implementation in `nanoglobin/genotype.py` is the semantic reference.
The full-sequence edit-distance stage already uses RapidFuzz's native implementation.
The optional Cython backend therefore accelerates the remaining class-by-evidence
and product-composition scoring stage.

Before entering the typed kernel, equivalent molecule observations are grouped by
product, compiled sequence and candidate-haplotype state. The Cython output is
converted back into the same `GenotypeClassScore` representation and must agree
numerically with the Python reference.

- `--backend python`: force the semantic reference;
- `--backend cython`: require the extension and fail closed otherwise;
- `--backend auto`: use Cython when representable, otherwise record an explicit
  Python fallback reason.

The current dense Cython representation uses a 64-bit candidate-haplotype mask. It
falls back to Python for catalogues larger than 64 named haplotypes rather than
silently truncating the candidate set.

## Commands

Uncalibrated/sensitivity-analysis use:

```bash
python scripts/genotype_amplicons.py \
  --compiled-json results/assay/compiled_products.json \
  --molecules-tsv results/assay/molecules/SAMPLE.molecules.tsv \
  --model-config examples/genotype_inference.example.yml \
  --backend auto \
  --posteriors-tsv results/assay/genotypes/SAMPLE.posteriors.tsv \
  --call-json results/assay/genotypes/SAMPLE.call.json \
  --summary-json results/assay/genotypes/SAMPLE.summary.json
```

Calibrated held-out use:

```bash
python scripts/genotype_amplicons.py \
  --compiled-json results/assay/compiled_products.json \
  --molecules-tsv results/assay/molecules/HELD_OUT.molecules.tsv \
  --model-config results/assay/calibration/calibrated_model.yml \
  --calibration-json results/assay/calibration/calibration.json \
  --backend auto \
  --posteriors-tsv results/assay/genotypes_calibrated/HELD_OUT.posteriors.tsv \
  --call-json results/assay/genotypes_calibrated/HELD_OUT.call.json \
  --summary-json results/assay/genotypes_calibrated/HELD_OUT.summary.json
```
